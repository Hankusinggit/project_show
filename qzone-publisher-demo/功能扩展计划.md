## 三、已排除项及理由

| 功能 | 排除理由 |
|------|---------|
| 相册批量复制 | 需要先构建"相册详情页 + 批量勾选模式 + 选目标相册页"三个页面，且核心价值在服务端权限位校验，前端只剩勾选 UI，投入产出比极低 |
| 匿问我答 | 属于资料卡模块，与发布器/Demo 主线无关；核心是多个网络协议加 H5 页面桥接，前端无可还原的独立价值 |
| 亲密空间三件套（主页头区/打卡/相册同步） | 独立的"亲密空间"页面体系（嵌套滚动/双头像/勋章墙），相当于再造一个 App；相册同步的核心是服务端异步执行 + 客户端定时轮询状态，纯前端无意义 |
| 相册底部 Tab | 需要完整的相册列表/照片流/视频流三套数据与网格布局，依赖相册模块整体存在 |

## 四、实施计划（按优先级分四批）

> 进度追踪：`[ ]` 待做 · `[x]` 已完成并验证

### 第一批：低成本高还原（先做，全是现有页面的增强）

#### 1. 同步入口完整约束规则 ⭐ 低 · 0.5天 `[~] 已砍掉（纯条件分支无算法/交互深度，时间留给高价值项）`
**功能**：同步到 QQ 签名 / 微信朋友圈

Demo 现在只有图标点击 + 提示。补齐真机的完整状态机：

| 规则 | 实现 |
|------|------|
| 选中态 = 彩色图标，未选中 = 灰色 | 切换图标颜色（QQ→品牌蓝，朋友圈→品牌绿） |
| 可见范围切到「私密」→ 图标置灰半透明 + 点击拦截 | 监听当前可见范围状态 |
| 切到私密时已勾选的自动取消 + 提示「已设置权限的说说不能进行同步」 | 从谁能看见页返回时触发重置 |
| 设置了定时/自动删除 → 朋友圈自动取消勾选（QQ签名不受影响） | 从发表设置页返回时检查 |
| 点朋友圈 + 有时效设置 → 拦截 + 提示「设置了时效的说说无法同步到微信」 | 点击时校验 |
| 发表成功 → 两个开关重置 | 发表成功回调里重置 |

**理由**：全部是纯前端状态规则，真机上是一张完整的规则矩阵表可直接照抄，是展示"业务状态机"能力的最佳素材。

#### 2. AI 声明 + 发表设置状态回显 ⭐ 低 · 0.25天 `[x] 已完成`
**功能**：发表设置右侧文案动态拼接

| 定时 | 自动删除 | AI | 右侧文案 |
|------|---------|-----|---------|
| 关 | 关 | 关 | （空） |
| 开 | 关 | 关 | 「07月14日 15:30 发表」 |
| 开 | 开 | 关 | 「定时发表/自动删除」 |
| 关 | 关 | 开 | 「已声明」 |
| 开 | 开 | 开 | 「定时发表/自动删除/已声明」 |

同时补一个细节：AI 声明开关**随草稿保存/恢复**（它是内容属性，跨会话恢复合理）；而同步开关**不随草稿持久化**（每次进入默认关闭，避免遗忘导致意外同步）——两者行为刻意不同。

**理由**：纯字符串拼接 + 一个状态字段，很快改完，但让"发表设置"从静态摆设变成活状态。

#### 3. 拍照支持 ⭐ 低 · 0.25天 `[x] 已完成（随选图器一起实现）`
**功能**：选图时直接拉起相机拍照

浏览器的文件选择控件加上相机唤起属性，移动端可直接拉起系统相机，桌面端会出现摄像头选项。

实现：照片方块附近加入口 → 拉起拍照 → 拍完的图进九宫格。

**理由**：一个 HTML 属性的事，但补齐了真机选图器的"拍照"入口闭环。

### 第二批：发布器核心交互（中等难度，简历亮点）

#### 4. 小图拖拽排序 ⭐⭐⭐ 中高 · 1天 `[x] 已完成（LazyListState 数据驱动 + FLIP 实时避让）`
**功能**：九宫格图片长按拖拽换位

Demo 现在的图片九宫格只有删除角标。补齐真机交互：

- **长按进入编辑态**：所有缩略图显示删除按钮（编辑态"粘住"——进入后不自动退出，删光图再选新图仍是编辑态）
- **长按拖拽**：拖拽换位（HTML5 拖放或指针事件实现九宫格内移动）
- **拖拽反馈**：被拖项放大 1.1 倍 + 阴影
- **数据同步**：拖完更新图片数组顺序（先取出元素再插入目标位置，含越界与原位拦截）
- **边界**：拖到自身位置不动；目标越界拦截

**理由**：纯手势 + 数组操作，无后端。拖拽排序在前端面试里是高频考点，放作品集里分量足。

#### 5. @好友输入检测 + 整段删除 ⭐⭐⭐ 中高 · 1天 `[x] 已完成（at-input.js 三段算法 + 全屏选择好友页）`
**功能**：@ 交互的三段核心算法

这是正式项目里**最值得移植的纯算法**，三段逻辑全是字符串处理：

1. **输入 `@` 自动唤起好友选择器**：只处理"新输入了恰好一个字符且是 @ "的情况（用新旧文本公共前缀长度定位插入点），粘贴大段含 @ 的文本不误触发
2. **@昵称 整段删除**：退格落在「@昵称 」段内 → 整段删除而非逐字符；按昵称长度降序匹配 + 前瞻断言（@ 后面必须跟空白/另一个@/结尾）防止「@小」误匹配「@小明」
3. **同名好友顺序分配**：两个同昵称好友按文本中出现顺序一一对应分配（先选先进队列、逐个消费），队列耗尽兜底为纯文本不崩溃

**理由**：正则前瞻断言、特殊字符转义、长度降序这些细节是真实业务打磨出来的，直接 JS 化就是一段展示功力的代码。Demo 的输入区已有 @ 蓝字插入，补上检测/删除逻辑即闭环。

#### 6. 发布器内大图预览 + 删除 ⭐⭐ 中 · 0.5天 `[x] 已完成`
**功能**：已选图片全屏预览、预览中删除

复用现有 Gallery 组件，加"发布器模式"：

- 点击九宫格缩略图 → 全屏预览（从点击的那张开始）
- 顶栏：返回 + 「2/5」计数 + 右侧删除按钮
- 删除 → 确认弹窗 → 从已选列表移除 → 自动跳到下一张（删的是最后一张则跳上一张）
- 删空 → 预览自动关闭
- **删除过渡保护**：切换动画期间冻结页码更新，避免异步回调把当前页写错（真机踩过的坑）

**理由**：Gallery 已有 80% 能力，只差删除交互和发布器入口。删除后跳转目标计算 + 空列表关闭的边界处理是精髓。

### 第三批：发表设置完整化（中等难度）

#### 7. 定时发表日期选择器 + 自动删除确认弹窗 ⭐⭐ 中 · 0.5天 `[x] 滚轮选择器已完成（含到点隐藏/下拉揭示/时光机校验）；自动删除确认弹窗待做`
**功能**：发表设置的两个弹窗交互

- **定时发表开关**：开启 → 弹出日期时间选择（滚轮样式），限制最多未来 10 天
- **自动删除开关**：开启 → 居中确认弹窗「发表后，该说说将在24小时后自动删除，该设置不可撤回」，点取消则开关回退
- 设置变化实时回传发布器主页（右侧文案即时刷新，不等退出设置页）

#### 8. 原画上传开关（黄钻特权模拟） ⭐⭐⭐ 中 · 0.5天（简化） `[x] 已完成（主页黄钻卡，含视频显隐 + 删视频自动重置）`
**功能**：黄钻用户的视频原画质开关

Demo 无真实视频上传，做**条件显隐 + 自动重置**的完整状态机即可：

- 模拟"选中视频"（图片选择入口区分照片/视频类型）
- 已选内容含视频时 → 设置区出现「上传原画视频」开关（带黄钻样式图标）
- 删掉视频 → 开关隐藏 + 勾选自动重置关闭（防止"已勾选但不可见"的脏状态提交）
- 默认关闭、不随草稿持久化（原画显著增大体积，不应无感知恢复）

**理由**：还原的是"条件可见 + 自动重置"这套守卫模式，视频本身是假的没关系，状态机是真的。

## 六、架构对接说明

所有新功能按现有组件化结构落位：

```
js/
├── publisher.js        ← 第一/三批改动集中在此（sync规则/设置回显/拖拽/预览删除）
├── feed.js             ← 编辑说说入口
├── gallery.js          ← 发布器预览模式（删除/计数）
└── （新增）at-input.js  ← @好友检测/整段删除算法（独立算法模块，便于展示）
```

@好友算法建议单独拆文件——它是唯一"原封不动照抄正式项目逻辑"的模块（正则 + 队列 + 前瞻断言），单独成文件放简历里最有说服力。
